# Phase 1 · 토요일 보강 우선 개발

작성일: 2026-09-15

Figma: [Pages - Phase 1](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=48-2114)

토요일 보강 운영을 최우선 개발한다. 사용자 확정: 보강은 토요일에만 열린다. 기존 전체 범위는 유지하되 이번 단계는 토요일 보강 등록·인계·결과 기록과 근무 편성에 집중한다. 원본 디자인을 보존하고 별도 Figma 페이지에 필요한 화면만 복제·정리했다.

## 역할별 흐름

- 강사: 로그인 → 학생 선택·보강 등록 → 일정·자료 준비 → 보강 결과 → 알림장 작성 → 학부모 안내 확인.
- 관리자: 학생 검색·등록 → 보강에서 선택 가능. 근무 순서 설정 → 편성 미리보기·확정 → 날짜별 대체·휴무 조정.
- 실제 로그인 후 권한으로 메뉴를 제한한다. 안내판의 역할별 링크는 디자인 검토용이다.

## 개발에 포함할 최소 기반과 완료 조건

- 관리자·강사 계정과 기본 강사 명단을 준비한다. 학생 목록·등록 UI를 이번 단계에 포함한다. 관리자는 이름·담임·재원 상태를 필수로 등록하고 학교·학년·보호자 연락처·수업 일정·메모를 함께 기록한다. 이름만으로 중복 학생을 차단하지 않고 기존 명단을 확인하도록 한다.
- 등록 완료 후 학생 식별자로 보강과 알림장을 연결한다. 학생 선택에서 학교·담임으로 동명이인을 구분한다. 강사는 담당 학생 및 자신에게 배정된 보강의 학생 범위에서 기록하며 관리자는 전체를 관리한다. 학생 수정·삭제 상세 UI와 세부 권한은 후속 상세 설계다.
- 보강 결과에서 알림장 작성 시 학생·보강일·근무자·출결을 가져오되 안내 내용은 확인 후 저장한다. 기존 알림장이 있으면 새로 중복 생성하지 않고 이어 쓴다. 보강 상태와 알림장 작성·안내 상태를 별도로 저장한다.
- 알림장은 진도·활동·완료 여부·과제(없음 명시)·사진/영상·학부모 안내·비공개 인계 메모를 기록한다. 임시 저장과 작성 완료를 구분한다. 미리보기·복사·외부 전달 대상에 내부 메모가 포함되지 않아야 한다.
- 실제 전달 후 채널·일시·수신 대상을 기록해야 안내 완료가 된다. 복사·저장만으로 안내 완료 처리하지 않는다. 자동 발송 및 학부모 로그인은 이번 단계에 포함하지 않는다.
- 보강은 토요일에만 열린다. 등록·수정·재예약에서 월–금·일요일은 선택·저장할 수 없다. 서버에서도 학원 시간대(Asia/Seoul) 기준 토요일과 운영일 여부를 검증한다. 잘못된 날짜 입력 시 “보강은 토요일에만 예약할 수 있습니다.”를 표시한다. 시간표의 지난/다음 이동은 7일 단위다.
- 일정 미정은 날짜 없이 저장할 수 있다. 날짜 지정 시 반드시 토요일이어야 한다. 결석일은 실제 결석일이므로 요일 제한을 적용하지 않는다. 같은 학생 시간 중복은 차단하고 강사의 여러 학생 동시 보강은 허용한다.
- 원래 담임과 당일 근무자를 구분한다. 근무표 연동 담당과 개별 지정 담당을 구분하여 날짜별 근무 변경의 영향을 보여준다.
- 일정 미정 → 예약 → 완료/불참 상태를 기록한다. 취소는 사유를 보존하고 이력으로 남긴다. 결과·자료 준비·변경 기록은 저장 후 다시 조회되어야 한다.
- 근무 로테이션의 시작일·순서·휴무·대체 규칙을 검증한다. 기본 순환과 비상 대체 순번은 별개이며 5번째 토요일·공휴일 처리는 관리자 확인을 거친다.
- 휴무 전 연결된 예약을 이동·취소하고, 대체 근무는 해당 날짜에만 적용한다. 이미 확정된 근무나 개별 지정 담당을 자동으로 덮어쓰지 않는다.
- 빈 목록·입력 오류·저장 실패·권한 없음·취소 확인은 별도 메뉴가 아닌 해당 페이지의 필수 상태로 구현한다.

- 시간표와 근무표를 세로 카드 목록으로 전환했다. 학생별 시간·담임·결석일·교재·자료 상태와 날짜별 근무자를 가로 스크롤 없이 확인한다.
- 본문만 세로 스크롤하고 저장·등록·이동 버튼은 하단에 유지한다. 버튼 높이는 48px, 입력 글자는 16px, 일반 본문은 14–16px이다.
- 등록과 결과 기록은 한 열 폼이다. 원래 담임과 근무표 연동 담당을 구분하고, 자료 준비·진행 상태·결과 사유를 기록하도록 구성했다.
- 실제 웹 구현에서는 최소 360px부터 화면 폭에 맞춰 재배치한다. 입력 시 모바일 키보드가 필드를 가리지 않도록 초점을 스크롤하고 하단 안전 영역을 확보한다. 390px 시안 검사 결과를 다른 기기의 실제 작동 검증으로 간주하지 않는다.
- 모바일 내부 링크, Noto Sans KR, 가로 경계 및 의도한 스크롤 영역 외 세로 경계를 검사했다. 오류 없음. 로그인·시간표·등록·관리자 화면을 렌더링해 확인했다.
- 날짜 선택, 필터, 순서 변경, 드롭다운, 인증·저장은 아직 정적 표현이다. 역할별 시작 링크는 검토용이며 실제 권한을 변경하지 않는다.

## 후속 개발 범위

교재 주문·교재비 청구, 수업료 청구·납부, 회의 기록, 학생의 종합 학습 평가 관리, 정규 토요수업은 후속 단계다. 학생 등록과 보강 알림장은 이번 요청으로 Phase 1에 포함했다.

## 디자인 검증 및 한계

데스크톱 16개·모바일 16개·안내판 2개를 Phase 1 안에서 연결했다. 원본 전체 디자인과 보라색 브랜드 변수는 유지한다. 토요일 전용 선택 화면도 렌더링해 확인했고, 의도된 스크롤 외 영역 초과 및 잘못된 화면 이동 대상은 없다. 날짜 선택은 9월 19일 대표 화면 이동 시안이며 다른 날짜의 실제 반영·검증은 개발 대상이다.

프로토타입은 화면 이동 시연이다. 실제 저장·검색·필터·날짜 선택·결과 상태 변경·인증은 아직 구현되지 않았다. 근무표 연동 담당 선택, 자료 준비 체크, 휴무 상세 상태, 변경 이력의 구체적인 입력 상호작용은 개발 전 해당 페이지 안에서 상세화해야 한다.
