# 필수 업무 기능 명세 · v0.3

작성일: 2026-09-14 · 검토용 설계안

## 1. 확정된 범위 변경

사용자가 첨부 이미지의 **알림장 / 토요수업·보강 / 교재 주문·교재비 청구 / 수업료 청구·납부 확인**을 반드시 구현할 기능으로 지정했다. 따라서 이전의 알림장 링크만 제공, 교재·청구·수납 제외 방침은 폐기한다. 기존 학생 관리·로그인·회의 기록도 유지한다.

이 문서는 [기존 명세서](functional-spec-v1.md)를 보완한다. 충돌하는 경우 v0.3의 범위와 정책을 우선한다. 필수 기능의 존재는 확정이며, 세부 운영 정책은 아래 원본 근거와 제안을 구분해 검토한다. **현재 결과물은 Figma 시안이며 실제 저장·청구 발송·결제 처리 구현은 아니다.**

## 4. 알림장과 학습 이력

### 기능과 입력

| ID | 기능 | 필수 동작 |
| --- | --- | --- |
| DIA-01 | 작성 현황 | 날짜·클래스·담당·학생·작성 상태·안내 상태 필터. 해당 날짜 수업 대상 명단과 기록을 대조해 작성 필요·작성 중·작성 완료를 표시 |
| DIA-02 | 일별 기록 | 학생·수업일·수업 종류·담당·출결 필수. 회차는 약정/진행 회차로 기록. 학습 영역별 교재·진도·활동·완료 여부·숙제를 추가·수정 |
| DIA-03 | 과제와 첨부 | 숙제 있음/없음 구분. 교재·페이지·기한 기록. 영상·사진 첨부와 링크 확인. 북토크는 책 제목·영상·라이팅 사진을 안내 전 확인 |
| DIA-04 | 내부 메모 | 수업 전달 사항·학생 특이사항을 학부모 안내와 별도 필드에 저장. 안내문·복사·공유 자료에서 기본 제외 |
| DIA-05 | 안내 준비·기록 | 보호자에게 전달할 내용 미리보기·복사, 첨부 확인. 실제 안내 뒤 채널·일시·대상·처리자 기록. 저장/복사만으로 안내 완료 처리 금지 |
| DIA-06 | 출결·보강 연결 | 결석 기록에서 보강 생성 시 학생·원래 수업일을 넘긴다. 이미 연결된 보강은 기존 건으로 이동. 보강 결과와 일별 알림장을 연결 |
| LRN-01 | 커리큘럼·수업 흐름 | 학생별 영역·교재·진행 상태·요일별 수업 순서·담당 기록. 교재 교체 후 과거 알림장의 교재명은 유지 |
| LRN-02 | 평가 기록 | 시험 종류·응시일·점수/등급·결과지 링크 수동 저장. 시험 종류별 점수 척도를 구분하며 서로 다른 척도를 합산하지 않음 |
| LRN-03 | 월간 의견 | 대상 월, 학습 진도·태도·보완점·다음 계획 작성. 초안 → 검토 요청 → 검토 완료 → 안내 완료. 검토자·안내 이력 기록 |

기록의 작성 상태와 안내 상태를 분리한다. 안내 후 수정하면 수정본은 재안내 대기로 표시하고 과거 전달 내용과 발송 일시를 보존한다. 수업별 알림장을 구분할 수 있도록 학생·날짜뿐 아니라 수업 ID로 연결한다. 같은 날 원서 수업과 보강이 각각 있어도 하나가 다른 기록을 덮어쓰지 않는다.

**작성 필요 집계 전제:** 학생의 기존 자유 입력 시간표만으로 수업 대상을 추측하지 않는다. 요일·시작·종료·유효기간·종류·담당이 있는 정규 일정 또는 당일 수업을 등록하고, 그 일정에서 날짜별 수업 건을 생성해야 한다. 일정 예외·취소·추가 수업을 반영한다. 정규 일정 설정의 세부 편집 화면은 후속 디자인 대상이다.

현재 자동 발송이 확인된 외부 연결은 없다. 첫 구현은 백오피스에서 작성·안내문 생성·복사 및 수동 안내 이력을 제공한다. 랠리즈/카톡/문자 자동 발송이나 보호자 전용 포털은 별도 연결 결정이 필요하며, 이를 알림장 기능 자체의 제외 사유로 삼지 않는다.

## 5. 토요수업·보강과 근무

| ID | 기능 | 필수 동작 |
| --- | --- | --- |
| SAT-01 | 통합 시간표 | 같은 날짜에 정규 토요수업과 보강을 함께 표시. 유형·학생·전체 시작/종료·담임·결석일·교재·전달 메모·준비 상태 확인 |
| SAT-02 | 정규 토요수업 등록 | 학생·날짜·시간·담당·교재/메모를 등록. 결석일은 요구하지 않으며 보강 건수에 포함하지 않음 |
| SAT-03 | 수업 결과 | 정규/보강의 출석·불참·실제 진행 내용 기록. 보강은 원래 결석 수업에 연결. 정규 수업 결과는 알림장과 연결 |
| ROT-05 | 비상 대체 순번 | 기본 근무와 별도 순번 목록. 근무 불가 날짜에 다음 순번을 후보로 제시하고 관리자가 실제 대체 근무를 확정. 공휴일은 비상 배정 제외 |

같은 강사의 동시 학생 지도를 허용하되 동일 학생의 시간 중복은 차단한다. 원래 담임·원서 담당·실제 당일 강사를 구분한다. 근무 변경 시 그 근무를 따르는 **연결 예정 수업**을 함께 변경하고 개별 담당 지정·완료 기록은 자동 변경하지 않는다.

원본에서 확인된 것은 **비상 근무 순번**이다. 기존 시안의 기본 근무 순환까지 실제 운영으로 확정된 것은 아니다. 기본 근무 자동 순환, 5번째 토요일, 공휴일 이후 순번 이동, 대체 근무 후 보상/차례 변경은 관리자 설정안이며 확인이 필요하다. 기존 v0.2의 ‘휴무도 순번 소비’는 기본 편성의 미확정 제안으로만 유지한다. 비상 순번에 그대로 적용하지 않는다.

## 6. 교재 주문과 교재비

### 데이터와 상태

주문 요청: 학생·클래스·요청자·작성일·첫 진도일·주문 회차·일반/긴급·사유·주문처·메모. 항목: 교재명·판본/ISBN(선택)·권수·정가·할인율 또는 확정 단가·청구액.

가격 미확정 상태로 요청은 저장할 수 있지만 청구 확정은 불가하다. 금액은 원 단위 정수, 수량은 양의 정수이며 표시 금액과 저장 금액이 일치해야 한다. 단가 확정·할인 기준·원 단위 반올림 방식은 운영 정책으로 확정한다.

- 주문 상태: 요청 → 주문 완료 → 일부 수령/수령 완료 → 일부 배부/배부 완료. 취소는 별도 이력.
- 청구 상태: 대상 준비 → 청구 초안 → 확정/안내 대기 → 안내 완료. 주문 완료를 청구 완료로 취급하지 않는다.
- 납부 상태: 청구 전 / 미납 / 일부 납부 / 납부 완료. 잔액과 납부 기록에서 계산한다.

| BOK-02 | 관리자 주문 | 요청 건을 주문 회차·주문처로 모으고 실제 주문 후 주문일·주문처·참조번호 기록. 요청 저장만으로 외부 주문 실행하지 않음 |
| BOK-03 | 수령·배부 | 항목별 수령·배부 수량과 일시 기록. 주문 수량을 초과할 수 없고 부분 처리 상태 유지 |
| BOK-04 | 청구 준비 | 주문 항목을 학생별 청구로 연결. 항목별 단가·할인·합계 표시. 이미 청구된 주문 항목 중복 포함 방지 |
| BOK-05 | 교재비 안내 | 담당 강사가 상세내역·합계·첫 진도일 확인 후 안내문 준비. 실제 문자/카톡 안내 뒤 청구일·방법·대상 기록 |
| BOK-06 | 납부 확인 | 관리자가 실제 납부일·방법·입금자·금액·근거 확인 후 저장. 다른 이름으로 입금한 경우 학생과 입금자를 각각 기록 |
| BOK-07 | 통합 현황 | 주문 대기·주문 후 미청구·미납·확인 대기를 구분. 주문/청구/납부 날짜와 담당을 한 행에서 추적 |

주문 즉시 청구 대상은 생성하되, 실제 보호자 안내는 학생별/클래스별 주기에 따른다. 원본에 주문 후 즉시 준비와 월 1회 첫 차시 전 안내가 함께 있고 상시 청구 탭도 있어, **안내를 항상 즉시 자동 발송하는 정책은 채택하지 않는다.**

취소된 주문에 청구가 있으면 연결 청구를 함께 검토한다. 이미 납부한 금액이 있는 청구를 단순 삭제하지 않는다. 반품·환불은 원거래 참조와 관리자 정정/환불 기록을 남기며 외부 환불 실행은 별개다.

## 7. 수업료 청구와 결제 확인

청구: 요청 참조·확정 금액·청구 예정일·납부기한·확정자/시각·실제 발송일·채널·외부 청구서 참조. 첫 수업일은 학생의 학원 최초 등록일과 별개다.

납부: 청구 참조·실제 결제일·방법·실제 입금자 또는 현장 결제 담당자·카드사·금액·영수증/승인 참조·최종 확인자/시각. 원본의 ‘결제자’는 의미가 모호해 입금자와 처리자를 별도 필드로 구분하는 안이다.

랠리즈 처리: 미처리/처리 완료·처리자·일시·외부 참조. 최종 납부 상태와 별개다.

‘첫 수업 7일 전’은 현재 9월 시트의 제목 기준이다. 원본의 실제 발송일은 이 계산과 다른 사례가 있으므로 과거 데이터를 예정일로 강제 덮어쓰지 않는다. 과거 첫 수업일을 등록하면 예정일 경과로 표시하고 관리자 검토 후 실제 발송일을 기록한다.

형제 할인은 존재하지만 적용 대상·예외·중복 여부가 확정되지 않았다. 초기에는 할인금액·사유를 관리자가 확인하고, 모든 형제에게 일괄 적용하지 않는다. 수업 변경·중도 입회·보강으로 원비를 임의 자동 재계산하지 않는다.

## 8. 공통 청구·납부 안전 규칙

1. 청구 유형은 수업료/교재비로 구분한다. 같은 화면에서 조회하더라도 회계상 다른 항목을 이름만으로 합치지 않는다.
2. 최종 청구액 = 확정 항목 합계 + 승인된 가산 − 승인된 할인. 잔액 = 최종 청구액 − 유효한 확인 납부 합계. 원 단위 계산과 화면 합계가 같아야 한다.
3. 부분 납부는 여러 건으로 기록한다. 초과 입금은 해당 청구에 잔액 이상 배정하지 않고 미배정액으로 관리자 확인한다. 형제 합산 입금은 각 학생/청구 배정액 합이 실제 입금액을 넘지 않게 한다.
4. 취소·정정·반품·환불에는 사유·원기록 참조·처리자를 남긴다. 이미 확정/안내된 청구 금액을 조용히 변경하지 않고 정정본과 재안내 필요를 표시한다.
5. 요청·확정·안내·납부 저장은 중복 클릭/재시도에도 중복 생성되지 않아야 한다. 동시에 확인한 경우 중복 납부를 막는다.
6. 현재 학생 정보를 수정해도 과거 청구의 수업 조건·금액·교재명은 달라지지 않는다. 민감한 증빙은 청구 접근 권한에 따라 제한한다.
7. 실제 카드 결제·계좌 출금·환불·문자 발송·교재 구매는 이 디자인 작업에서 수행하지 않았다. 구현의 기본안은 업무 기록 및 외부 처리 확인이며, 자동 실행은 서비스 연결과 운영 방식을 별도로 확정한다.

## 11. 구현 전 확정할 정책

- 교재비 안내: 주문 후 즉시/월별 일괄/클래스별 상시 여부와 가격 확정 주체. 기능은 모두 지원 가능하도록 청구 대상 준비와 실제 안내를 분리한다.
- 수업료: 수강 계약/청구 차수 기준, 할인·중도 변경·환불 규칙, 주당 수업시간별 요금표. 원본의 개별 금액을 공통 요금표로 추정하지 않는다.
- 알림장: 강사별 작성·검토 책임, 보호자 안내 채널, 첨부 보관 기간, 월간 검토자와 기한.
- 토요일: 기본 근무와 비상 순번 운영 관계, 다섯 번째 토요일, 공휴일 이후 순번, 대체 후 차례/보상 처리.
- 외부 연결: 랠리즈·카톡·문자·결제 서비스의 API 및 권한 확인. 확인 전에는 수동 처리 사실을 정확히 표시한다.

권장 구현 순서는 **계정·학생·수업 일정 기반 → 알림장과 토요수업/보강 → 교재 주문·청구 → 수업료·납부 확인 → 회의·후속 업무 연결**이다. 이는 작업 순서이며 필수 기능을 다음 단계로 제외한다는 의미가 아니다.
