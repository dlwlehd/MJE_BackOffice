작성일: 2026-09-14

우선 개발 범위(2026-09-15): [Phase 1 · 토요일 보강·학생 등록·알림장](phase-1-weekend-makeup.md). 보강은 토요일만 운영한다. Figma의 `Pages - Phase 1`에 날짜 선택을 포함한 14종 화면을 데스크톱 16개·모바일 16개 화면안으로 정리했다. 기존 전체 범위는 후속 단계까지 보존한다.

## 합의한 초기 범위

학생 관리·로그인·회의에 더해 **알림장, 토요수업·보강, 교재 주문·교재비 청구, 수업료 청구·납부 확인은 모두 필수 구현 범위**다. v0.3 사용자 요청으로 종전의 알림장 링크만 제공 및 청구·수납 제외 방침을 폐기했다. 외부 자동 발송·결제·구매 연동은 별도 결정한다.

## 필수 업무 확장 · v0.3

원본 업무 문서와 학생·알림장 시트를 다시 확인하고, 문서에 연결된 현재 교재 주문·청구 시트와 2609 수업료 청구 시트도 확인했다. 사용 중지 탭은 현재 절차에서 제외했다.

- [알림장](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=24-620): 작성 현황 → 진도·과제·출결·첨부·내부 메모 → 학부모 안내 미리보기·실제 안내 기록. 학생별 커리큘럼·평가·월간 의견도 추가했다.
- [교재 주문·청구](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=24-875): 첫 진도일·교재·수량·할인 → 주문 → 청구 준비·안내 → 관리자 납부 확인. 강사/관리자 목록을 구분했다.
- [수업료·납부](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=24-1130): 첫 수업일·청구 요청 → 관리자 검토·확정·발송 기록 → 실제 결제 확인 → 랠리즈 납부처리 확인.
- [토요수업·보강](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=13-429): 정규/보강 유형을 구분하고 정규 수업 등록을 추가했다. 근무 화면에 기본 편성과 비상 대체 순번을 분리해 표시했다.
- 총 15개 화면 추가. 현재 31개 업무 화면 + 디자인 안내. 전체 메뉴와 학생 상세의 학습 이력 진입을 연결했다.
- 모든 학생·가격·거래·날짜 예시는 검토용이다. 실제 외부 메시지 발송, 청구, 납부 처리, 주문은 수행하지 않았다.
- v0.3 최종 검사: 총 32개 프레임(업무 화면 31개 + 안내), 보이는 텍스트 1,377개 모두 Noto Sans KR. 검사상 부모 영역 초과와 잘못된 화면 이동 대상 없음. 새 화면별 주요 영역과 알림장·교재·수업료 전체 화면을 렌더링해 확인했다.

추가 화면 노드와 후속 상세 디자인 범위는 [확장 명세 9절](required-workflows-v0.3.md#9-figma-화면-연결)에 기록했다. 아래 v1/v0.2 검증 수치는 당시 작업의 기록이며 현재 전체 화면 수를 뜻하지 않는다.

## 2026-09-14 추가 요청 반영

- [날짜별 보강 시간표](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=13-429): 시작 시간별 명단, 학생별 종료 시간·결석일·담임·교재·전달 사항·자료 준비 상태. 상단에 당일 근무자·근무 시간과 공통 메모를 표시한다.
- [관리자 토요일 근무](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=13-493): 순서·적용 기간·근무 시간 설정, 날짜별 기본/실제 강사 비교, 대체 근무·편성 미리보기 진입.
- [날짜별 변경](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=13-557): 대체 강사·시간·사유와 연결 보강에 미치는 영향 표시.
- [편성 미리보기](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=18-697): 기존 확정·대체 근무를 보존하고 신규 날짜만 편성하는 안.
- 기존 보강 목록에 시간표 전환을 추가하고 관리자 학생 목록·등록 및 신규 관리자 화면에 토요일 근무 메뉴를 추가했다.
- 기본안은 토요일 1명 순환 근무이며, 대체와 휴무는 이후 주차 순서를 바꾸지 않는다. 실제 운영 정책 확정 전 검토가 필요하다.
- 첨부 이미지에서 동시 보강을 확인해 강사 시간 중복 차단 제안을 철회했다. 같은 학생의 중복 시간만 차단하는 안으로 명세서를 수정했다.
- 새 화면은 가상 데이터로 구성했다. 저장·날짜 이동·순서 조정은 실제 기능이 아니며, 주요 화면 이동만 연결했다. 휴무 선택 후 상세 상태와 토요일 보강 등록의 담당 방식 입력은 후속 상세 디자인 대상이다.

## 디자인에서 제안한 권한과 흐름

- 로그인은 공통 화면. 학원에서 발급한 계정의 권한으로 접근 범위를 판별한다. 역할 선택으로 관리자 권한을 얻는 UI는 만들지 않는다.
- 관리자는 전체 학생을 조회하고 학생 등록과 담당자 배정을 한다.
- 강사는 담당 학생 중심 목록, 보강, 회의 기록을 이용한다. 상세 정보의 수정 가능 항목과 담당 외 학생 조회 범위는 구현 전 확정이 필요하다.
- 담임과 원서 담당을 별도로 표시한다.
- 보강은 결석일과 연결하고, 일정 미정으로 먼저 저장할 수 있다. 날짜를 지정할 때는 시작·종료 시간도 입력한다.
- 회의는 안건별 논의·결정, 관련 학생, 담당자·기한이 있는 후속 업무를 기록한다.
- 화면의 인물·연락처·학교·수업 정보는 검토용 예시이며 실제 데이터 이관 결과가 아니다.

## 디자인 기준

- Noto Sans KR, 흰색 업무 표와 보라·인디고 브랜드 강조, 연보라 배경, 얇은 구분선. 2026-09-15 로고 참고 이미지에 맞춰 색상을 변경했다.
- Simple Design System의 버튼·입력·텍스트 영역을 인스턴스로 재사용했다.
- taste-skill 패키지의 minimalist-ui에서 업무 화면에 맞는 시각 지침을 적용했다. 홍보 페이지용 애니메이션이나 대형 히어로 구성을 업무 화면에 강제하지 않았다.
- 전체 범위는 desktop 1440px 기준. Phase 1은 390×844 모바일 16개 화면을 추가했다. [모바일 안내](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=51-2249). Phase 1 외 모바일 화면은 후속 설계 대상이다.

## 2026-09-15 로고 기반 색상 변경

31개 업무 화면과 디자인 안내에 공통 색상을 적용했다. 로그인 소개 패널은 짙은 보라색, 주요 버튼·선택 메뉴는 선명한 보라색, 시간표·근무표·청구 표의 강조 영역은 연보라색이다. 오류·확인 필요·완료의 의미를 가진 상태색은 유지한다.

| Figma 색상 변수 | 색상 | 용도 |
| --- | --- | --- |
| brand/primary | #5B3FD6 | 주요 버튼, 선택 메뉴, 임시 MJE 글자 |
| brand/deep | #35216F | 로그인 소개 패널 |
| surface/sidebar | #F7F5FC | 사이드바 |
| surface/subtle | #F5F3FA | 표 머리글, 보조 영역 |
| surface/selected | #ECE6FF | 선택·주요 정보 강조 |
| text/primary | #252036 | 제목·본문 |
| text/secondary | #686174 | 설명·보조 문구 |
| border/default | #DED9E8 | 입력란·표 구분선 |
| text/on-brand | #FFFFFF | 보라 배경 위 글자 |

Figma의 `MJE · Brand` 색상 변수 9개로 관리한다. 참고 이미지를 바탕으로 정한 제안 팔레트이며 원본 로고의 공식 색상 추출 결과는 아니다. 로고 파일은 사용자가 추후 제공한다. 현재 MJE 텍스트 자리를 유지하며, 작은 참고 이미지를 확대하거나 로고를 임의 재제작하지 않았다. 원본 수령 후 로고 비율·여백과 최종 브랜드 색을 맞춘다.

검증: 전체 32개 프레임, 보이는 텍스트 1,377개, 검사상 부모 영역 초과 및 잘못된 화면 이동 대상 없음. 로그인·보강 시간표·수업료·토요일 근무 화면을 렌더링해 확인했다. 흰색과 주요 보라색의 대비는 6.72:1, 짙은 보라색은 13.14:1이다. 실제 서비스 구현이 아닌 Figma 디자인 변경이다.

## 검증 및 한계

- 12개 화면과 디자인 안내를 생성했고 각 주요 화면을 렌더링해 확인했다.
- 최종 검사: 보이는 텍스트 415개는 모두 Noto Sans KR, 검사한 자동 레이아웃의 세로 경계 초과 없음, 존재하지 않는 프로토타입 이동 대상 없음.
- 주요 메뉴·목록 상세·등록 화면·보강 일정 선택·역할별 미리보기 이동을 연결했다.
- 프로토타입은 화면 이동 시연이다. 로그인 검증, 폼 입력, 저장, 필터, 업무 완료 처리 및 외부 서비스 연동은 구현되지 않았다.
- 비밀번호 복구, 초대/계정 발급, 검색 결과 없음, 로딩, 등록 검증 오류, 삭제/취소 동작은 후속 상세 설계 대상이다.
