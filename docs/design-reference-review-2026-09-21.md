# 엠제이 일정 통합 디자인 — 유사 서비스 비교 점검

점검일: 2026-09-21

## 결론

현재 디자인은 보강·학사·상담으로 나눈 구조와 브랜드 일관성은 좋다. 월간 달력도 기간 일정, 일정 더보기, 상세 팝업을 갖추었다. 다음 개선의 핵심은 장식이 아니라 **누구의 어떤 일을 지금 처리하는지 명확히 하고, 선택한 대상의 기록까지 이어지게 하는 것**이다.

우선순위는 상담 대상별 작업 연결 → 상담 기록 입력 → 보강 처리 상태 → 연간 계획 가시화 → 공통 시각 체계와 모바일 완결성 순이다.

## 점검 범위와 한계

- 대상: Figma `Pages - 일정 통합 v2`의 19개 프레임. 최근 Google Calendar 참고 개선을 포함한다.
- 기준 파일: [현재 디자인 페이지](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=133-1528), `site-functional-spec-v2.md`, `site-design-v2.md`.
- 기존 운영 사이트와 새 Figma 시안은 서로 다른 산출물이다. 아래 지적은 새 시안에 대한 평가이며, 배포 사이트에서 동일 문제가 발생한다고 단정하지 않는다.
- 외부 서비스는 공식 공개 화면·기능 소개·도움말을 비교했다. 유료 관리자 계정으로 전체 작업을 수행한 비교는 아니다.
- Figma의 대표 화면 이동만 구현된 부분은 실제 저장 오류나 필터 오류로 평가하지 않았다. 다만 개발 전에 확정해야 할 상호작용은 구분해 기록했다.
- 이번 점검에서는 Figma와 운영 데이터를 수정하지 않았다.

## 유사 서비스에서 참고할 패턴

| 서비스 | 공식 자료에서 확인한 패턴 | 엠제이에 적용할 해석 |
|---|---|---|
| [Teachworks](https://www.teachworks.com/features/calendar) | 교사·학생·장소 필터, 가용 시간과 충돌 확인, 일정 선택 팝업의 보기·수정·완료 작업 | 일정 카드가 해당 학생의 출석·결과 처리 출발점이 되어야 한다. 학사 일정과 보강에 똑같은 편집 동작을 강요하지 않는다. |
| [TutorCruncher](https://help.tutorcruncher.com/en/articles/14183102-viewing-lesson-reports-for-specific-students) | 학생과 기간으로 수업 보고서를 모아 조회·내보내기 | 상담 이력을 대상자 중심으로 누적하고 날짜·유형으로 찾을 수 있게 한다. 수업 보고서 사례를 상담 기록 구조에 응용한 제안이다. |
| [Classcard](https://helpdesk.classcardapp.com/en/articles/11484137-how-to-navigate-the-student-app) | 모바일 달력에 일정 있는 날짜를 점으로 표시하고 선택 날짜의 상세를 아래에 표시 | 모바일은 날짜 선택 후 읽기 쉬운 목록으로 전환하는 구조가 적합하다. 해당 레퍼런스는 학생용 화면이므로 관리자 편집 기능의 근거로 사용하지 않는다. |

Google Calendar는 월간 탐색의 기준으로 유지한다. 학원 운영 작업은 위 서비스의 대상별 처리 패턴을 함께 참고하는 편이 적절하다. 외부 서비스의 결제·급여·마케팅 기능까지 가져올 필요는 없다.

## 유지할 강점

- 보강·학사 일정·상담의 세 영역이 분리되어 있어 업무 범위를 이해하기 쉽다.
- 토요일 보강 규칙과 출석/완료의 별도 상태를 유지하고 있다.
- 월간 달력의 여러 날에 걸친 일정 막대, 더보기, 상세 팝업은 일정 밀도가 올라가도 사용할 수 있는 기반이다.
- 상담 기록 옆에 이전 이력을 배치한 방향은 적절하다.
- 한국어 서체와 보라색 브랜드가 일관된다. 전면 교체보다 상태·선택·행동의 위계를 보강하는 것이 효율적이다.

## 우선 개선 사항

P1은 핵심 업무 수행과 원래 요구 충족에 영향을 주는 설계 문제, P2는 탐색·가독성·사용 범위 개선이다. 이번 검토에서 확인한 운영 장애나 데이터 손실이 없어 P0는 지정하지 않았다.

### P1-1. 상담 목록의 작업 대상이 불명확하다

[상담 목록](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=133-1535)

**현재:** 하단 공통 버튼인 `결과 기록 열기`, `대상자 이력`이 있지만 어느 행을 선택했는지 드러나지 않는다. 대표 프로토타입에서는 고정 예시 대상으로 이동한다. 예약·결과 미기록·취소도 유사한 텍스트로 표시된다.

**영향:** 상담 종료 후 미기록 건을 처리할 때 대상자와 회차를 다시 확인해야 한다. 개발자가 전역 버튼의 대상을 임의로 해석할 여지도 있다.

**개선:** 행마다 이름, 상담 유형, 일시, 담당자, 상태를 정렬하고 `결과 작성` 또는 `기록 보기`를 직접 배치한다. 이름을 누르면 대상자 전체 이력으로 이동한다. 취소 건은 결과 작성 대신 상세 확인을 제공한다.

**완료 기준:** 목록에서 서로 다른 두 상담을 열었을 때 해당 대상자·일시가 상세 상단에 유지된다. 결과 미기록만 모아서 다음 건을 처리하는 흐름이 표현된다.

### P1-2. 상담 기록 양식이 실제 기록 분량과 맞지 않는다

[상담 결과·이력](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=133-1537)

**현재:** 상담 내용·결과 요약·합의 사항이 한 줄 입력 형태이고, 후속 조치·담당·기한이 하나의 입력 영역에 묶여 있다. 이전 기록은 요약 예시 위주다.

**영향:** 긴 내용을 읽고 고치기 어렵고, 다음 상담 때 누가 언제 무엇을 하기로 했는지 빠르게 찾기 어렵다.

**개선:** 내용과 결과는 여러 줄 입력으로, 후속 조치는 내용/담당자/기한으로 분리한다. 상단에 대상자·상담 상대·일시를 고정적으로 표시하고, 이력은 날짜별 요약을 펼쳐 전문을 볼 수 있게 한다. 저장 후 기록 시각을 표시한다.

**완료 기준:** 여러 문단의 상담 기록과 두 개의 후속 조치를 넣어도 읽을 수 있다. 신규·학부모·학생 상담의 과거 기록을 구분해 다시 찾을 수 있다.

### P1-3. 보강 대시보드가 현황과 처리 작업을 충분히 연결하지 못한다

[보강 대시보드](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=133-1529)

**현재:** 시간대별 학생 카드가 반복되고, 인원이 많은 열 때문에 하단 작업 버튼이 길게 밀린다. 학생별 담당자 정보와 작업 버튼 연결이 약하다. `여유`와 `과밀 주의`의 시각적 차이도 작다.

**영향:** 등원 시에는 출석 확인, 종료 후에는 결과 입력이 필요한데, 지금 처리할 카드를 빠르게 가려내기 어렵다. 여러 시간대에 반복된 학생을 실제 학생 수와 혼동할 수 있다.

**개선:** 카드에 담당자·출석 상태·완료 상태를 구분하고 학생별 상세 진입을 제공한다. `출석 미확인`, `결과 미기록` 필터와 건수를 배치한다. 시간대 배정 건수와 고유 학생 수는 명칭으로 구별한다. 전체 초기화는 일반 작업과 분리한 더보기 메뉴에 둔다.

**완료 기준:** 6명 이상 배정된 시간대에서도 특정 학생의 출석과 결과를 바로 처리할 수 있다. 출석만 기록한 학생을 완료 학생으로 오해하지 않는다. 동일 교사가 동시에 여러 학생을 지도하는 보강을 무조건 충돌로 막지 않는다.

### P1-4. 연간 화면이 12개월 계획 도구로는 부족하다

[연간 학사 일정](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=133-1533)

**현재:** 12개 미니 달력과 월별 예시 일정으로 구성되어 있고, 날짜 글자는 10px이다. 일정이 있는 날짜, 시험 집중 기간, 방학 범위가 연간 화면에서 충분히 드러나지 않는다.

**영향:** 원래 목표인 ‘12개월 일정을 미리 짜기’보다 날짜를 확인하는 용도에 가깝다.

**개선:** 일정 날짜에 유형별 표시, 월별 일정 수와 주요 기간 요약을 추가한다. 월을 선택하면 읽기 쉬운 일정 목록과 등록·수정으로 이어지게 한다. 시험과 방학이 겹치면 같은 기간의 두 일정을 확인할 수 있게 한다. 월별 주요 일정 목록을 병행해 작은 날짜를 모두 읽지 않아도 계획을 파악하도록 한다.

**완료 기준:** 매탄중 시험, 엠제이 방학, 테스트 일정을 각각 여러 달에 배치한 사례에서 어느 달이 비어 있고 어느 기간에 일정이 겹치는지 파악할 수 있다.

### P2-1. 선택 상태와 업무 상태의 시각적 위계를 정리해야 한다

[월간 학사 일정](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=133-1532), 공통 내비게이션

**현재:** 메뉴와 필터가 비슷한 연한 버튼으로 보인다. 보라색이 브랜드·일정·여유·주의 등 여러 의미에 사용된다. 월간 일정 텍스트는 12px이다.

**개선:** 현재 메뉴는 채움 또는 선으로 분명히 표시하고, 기본·보조·위험 작업 버튼을 구별한다. 일정 유형 색상과 처리 상태 색상은 별도 규칙으로 정의한다. 예: 시험=청색, 방학=청록, 테스트=보라; 주의=호박색, 취소=중립색. 색상과 함께 유형/상태 문구를 유지한다. 본문 14–16px를 우선 검토하고 작은 글씨는 보조 정보에 제한한다.

**완료 기준:** 현재 메뉴, 적용된 필터, 오늘, 선택한 날짜가 서로 구별된다. 색을 보지 않아도 일정 유형과 상태를 알 수 있다. 실제 크기에서 긴 한국어 일정 제목과 넘침 표시가 읽힌다. 색 대비는 토큰 확정 후 별도로 측정한다.

### P2-2. 예약 입력 요소를 실제 선택 방식으로 구체화해야 한다

[상담 예약](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=133-1536)

**현재:** 담당자, 날짜, 시간 등이 일반 한 줄 입력처럼 표현되어 있고 시작·종료가 한 영역에 묶여 있다.

**개선:** 대상자 검색, 담당자 선택, 날짜 선택, 시작/종료 시간 선택을 구분한다. 상담 중복이 있으면 겹치는 담당자·시간·예약과 수정 방법을 보여준다. 신규 상담은 재원생 선택을 강제하지 않는다.

**완료 기준:** 빈 상태, 선택 완료, 필수값 누락, 종료 시간이 시작보다 빠른 경우, 상담 시간 중복을 각각 표현한다.

### P2-3. 모바일에서도 한 가지 업무를 끝낼 수 있어야 한다

[모바일 학사](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=134-2452), [모바일 상담](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=134-2531), [모바일 보강](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=134-2561)

**현재:** 조회 화면이 중심이며 입력·저장까지 이어지는 모바일 화면은 부족하다.

**개선:** 작은 월간 달력 아래 선택 날짜의 목록을 중심으로 구성한다. 상담 결과 작성 또는 보강 출석 처리 중 실제 모바일 사용 빈도가 높은 흐름부터 상세·입력·저장 완료 화면을 연결한다.

**완료 기준:** 390px 화면에서 가로 스크롤 없이 대상 확인 → 입력 → 저장 확인 → 목록 복귀가 가능하다. 키보드가 올라와도 저장 동작에 접근할 수 있다.

## 첫 수정 묶음 제안

1. **상담 목록 + 결과 기록:** 행별 작업과 대상자 연결, 긴 기록, 후속 조치, 이전 이력을 함께 완성한다.
2. **보강 대시보드 + 학생 상세:** 출석/결과 미처리 상태와 바로 처리 동선을 완성한다. 공통 메뉴·버튼·상태 토큰도 이때 정리한다.
3. **연간 학사 + 월간 연결:** 12개월 계획 가시화, 월별 상세, 일정 등록·수정·삭제의 연결을 완성한다.
4. **모바일 대표 흐름:** 위 작업 중 하나를 휴대폰에서도 끝낼 수 있도록 확장한다.

## 후속 검증 시나리오

| 업무 | 확인할 결과 |
|---|---|
| 토요일 보강 시작 | 담당자가 미출석 확인 대상을 찾아 해당 학생을 처리한다. |
| 보강 종료 | 출석 완료/결과 미기록 학생만 찾아 결과를 저장한다. |
| 상담 종료 | 해당 회차의 결과를 작성하고 대상자 과거 기록을 다시 확인한다. |
