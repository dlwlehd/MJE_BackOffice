# 엠제이 일정 관리 사이트 기능 명세 v2

최신 시각 설계: [shadcn/ui 구현 기준 v3](site-design-v3.md). 기능 범위는 본 명세를 유지하며, 탐색은 좌측 사이드바, 등록·수정은 오른쪽 패널 중심으로 변경했다.

작성일: 2026-09-21. 상태: 설계안, 실제 서비스 구현 전.

## 1. 목적과 범위

현재 [토요 보강 실시간 현황판](https://sat-tutoring-krxbzcsy.manus.space/)의 업무 기능을 유지하고, 12개월 학사 일정과 상담 예약·누적 기록을 추가한다. 기존 BackOffice는 시각 참고자료로 사용하며 Figma의 새로운 페이지에서 설계한다. 기존 문서와 디자인은 보존한다.

이번 사이트의 핵심 메뉴는 **토요 보강 / 학사 일정 / 상담 관리**다. 학생·직원 계정은 공통 기반이다. 이전 명세의 알림장·근무 관리·청구·회의는 삭제된 요구가 아니며, 이번 화면 개편 범위와 별도 관리한다. 외부 자동 발송, 결제, 실제 데이터 이관은 이번 산출물이 아니다.

표기: `확인`은 2026-09-21 원본 화면에서 확인한 기능이다. `유지`는 새 사이트가 제공해야 하는 기능이다. `제안`은 상세 정책이 없어서 정한 구현 기본안이다. 조회와 수정 창만 확인했으며 원본 데이터 등록·저장·삭제·초기화는 실행하지 않았다. 실시간 동기화, 서버 검증, 인쇄 결과와 초기화 후 동작은 별도 검증이 필요하다.

### 인원과 시간 계산

교시별 인원은 해당 교시와 시간이 겹치는 고유 학생 수다. 10:30~12:30 예약은 1·2·3교시에 표시된다. 종료 시각과 다음 시작 시각만 같은 경우 중복으로 계산하지 않는다 (`[시작, 종료)`). 교시별 인원과 순간 최대 동시 인원은 다르므로 이름을 구분한다. 동일 학생의 겹치는 예약은 차단하고, 한 강사의 여러 학생 동시 보강은 허용한다. 정기 수업도 정원 집계에 포함한다. 취소·삭제는 제외하며, 완료 여부로 과거 예약 인원을 소급 감소시키지 않는다.

주간 보관은 Asia/Seoul 기준 토요일 날짜에 귀속한다. 보관 재시도에는 중복 방지 키를 사용한다. 보관 자료를 현재 명단으로 자동 복원하지 않는다. 원본의 정확한 초기화 범위·보관 트리거는 화면만으로 검증되지 않았으므로 위 절차는 새 사이트의 제안이다.

예시 제목은 `매탄중 시험일`, `엠제이 방학`, `월말 Test`다. Figma 날짜는 가상 예시이며 실제 학사 정보가 아니다. 종료일은 시작일보다 빠를 수 없다. 종일 일정의 화면 종료일은 포함 일자다. 시간 지정 일정은 종료 시각이 시작보다 뒤여야 한다. 방학을 등록했다고 보강·상담을 자동 취소하지 않는다. 보강 휴무 적용을 선택하면 연결 예약을 보여주고 재배정/취소 후 확정하도록 한다(제안).

### 운영 흐름

연도 선택 → 12개월 계획 확인 → 일정 등록 → 대상·기간 검토 → 저장 → 해당 월에서 확인. 수정/삭제 뒤에는 다른 달에 걸친 기간 표시와 연결 예약 영향도 함께 확인한다.

### 달력 표시 규칙 (구글 캘린더 참고 개선)

상단에 오늘·이전/다음·연월·월간/12개월 전환·검색을 둔다. 왼쪽 미니 달력에서 날짜를 빠르게 선택하고 분류 체크박스로 표시 일정을 조합한다. 오늘은 학원 시간대 기준 원형 강조, 선택 날짜는 별도 선택 표시로 구분한다. Figma 예시에서는 오늘과 선택일이 2026-09-21로 같다.

종일·기간 일정은 상단 막대로, 시간 지정 일정은 시작 시각과 제목으로 표시한다. 기간 막대는 주 경계에서 나누되 이어짐을 표시하고 같은 일정 ID를 유지한다. 겹치는 기간은 행을 나누며, 남은 공간을 초과하면 +N개로 해당 날짜의 전체 일정을 펼친다. N은 해당 날짜에서 숨겨진 일정 수다. 기간 일정의 상세는 시작일부터 종료일까지 전체 기간을 보여준다. 이전/다음 달 날짜는 약하게 표시하고 주말은 옅은 배경으로 구분한다.

일정 선택 → 작은 상세창 → 수정 또는 삭제 확인으로 이동한다. 모바일은 날짜 아래 일정 유무를 표시하고 선택일의 모든 일정을 시간순으로 보여준다. 구글 계정·캘린더 데이터 연동은 이번 요청에 포함하지 않는다.

상담 시간은 토요일로 제한하지 않는다. 동일 상담자의 예약 시간이 겹치면 충돌을 보여주고 저장 차단하는 기본안이다. 취소된 예약은 충돌 집계에서 제외한다. 방학·보강 근무와의 충돌은 경고하고 운영자가 조정한다. 가족·동명이인은 이름만으로 병합하지 않는다. 학부모 상담은 상담 대상 보호자와 관련 학생을 각각 저장한다. 신규 등록 전환도 운영자가 기존 학생 후보를 확인한 뒤 수행한다.

완료 기준: 신규 예약 → 상담 결과 작성 → 기록 완료 → 대상자 타임라인에 누적 → 후속 예약 → 이전 기록과 다음 일정 동시 확인. 상담 내용을 학부모에게 자동 발송하지 않는다.

## 5. 공통 권한과 데이터

권한은 제안이며 실제 직원 역할을 확인해 확정한다. 관리자는 전체 일정·정기 등록·초기화·보관함·권한을 관리한다. 강사는 허용 학생의 보강·상담을 조회/작성하고 학사 일정을 조회한다. 상담 내용은 담당 상담자 및 관리자에게만 기본 공개한다. 담당 외 학생에 대한 예외 권한은 명시적으로 부여한다. 조회·변경·내보내기에도 서버 권한 검사를 적용한다.

주요 데이터: Student, Staff, RegularEnrollment, MakeupSession, Attendance, MakeupResult, WeeklyArchive, AcademicEvent, ConsultationSubject, ConsultationAppointment, ConsultationRecord, FollowUp, AuditLog. 모든 관계는 ID로 연결한다. 이름·연락처를 키로 사용하지 않는다. 예약과 상담 기록은 별도 엔터티이며 기록에는 버전을 둔다. 주간 스냅샷은 원본 학생이 수정되어도 당시 이름·결과가 유지된다.

## 6. 상태·접근성·모바일

- 로딩: 최종 달력/행 구조와 같은 스켈레톤. 실패: 재시도, 입력값 보존. 빈 목록: 날짜/필터 상태와 등록 진입 제공.
- 잘못된 입력은 필드 아래에서 설명. 미저장 이탈은 유지/나가기 선택. 저장 중 중복 제출 차단, 실패 시 성공 토스트 금지.
- 동시에 수정되면 최신 버전 충돌 안내 후 재조회 또는 다시 적용. 다른 직원의 결과를 조용히 덮어쓰지 않음.
- 키보드 이동, 명시적 라벨, 포커스, 44px 이상 조작 영역. 상태를 색만으로 구분하지 않음.
- 모바일 학사 일정은 월간 날짜 선택+선택일 목록, 연간은 월별 세로 목록. 보강은 교시별 세로 목록, 상담은 날짜별 예약 및 단일 열 입력.
- 공통 시각 기준: Noto Sans KR, 기존 MJE 보라색 브랜드 변수와 Simple Design System 버튼/입력 사용. DESIGN_VARIANCE 3, MOTION_INTENSITY 2, VISUAL_DENSITY 6. 홍보 사진·히어로·스크롤 연출은 업무 화면에 적용하지 않음.

## 7. 인수 시나리오

1. 10:30~12:30 보강 1건 등록 시 3개 교시에 표시되고 학생 합계는 1명, 학습 시간은 2시간이다.
2. 동일 학생의 11:00~12:00 중복은 차단, 다른 학생의 동시간 예약은 허용한다. 6명인 교시에는 과밀 문구가 나타난다.
3. 출석 체크만으로 보강 완료되지 않는다. 완료 결과를 저장 후 새로고침해도 내용이 유지된다.
4. 주간 보관 중 오류가 나면 현재 보강은 그대로 남는다. 재시도 후 보관/정기 일정이 중복되지 않는다.
5. 미래 연도의 12개월을 열고 학교 시험·방학·Test를 등록, 수정, 삭제하면 월간과 연간에 동일하게 반영된다.
6. 12월~1월 기간 일정이 양쪽 연도에 표시된다. 종료일 역전은 차단한다.
7. 신규 상담을 학생 등록 없이 예약하고 결과를 기록한 뒤 등록 전환해도 이전 상담 기록이 유지된다.
8. 세 상담 유형의 결과가 대상자별로 누적되며 후속 예약으로 이전 결과가 바뀌지 않는다.
9. 상담자 시간 충돌, 결과 미입력 완료, 권한 없는 상담 조회를 각각 차단한다.
10. 모바일 360px에서 가로 잘림 없이 핵심 조회/입력 가능. 인쇄/PDF에서 조작 버튼과 비공개 상담 내용이 의도치 않게 출력되지 않는다.

## 8. 확인이 필요한 운영 정책

원본 초기화의 실제 범위와 주간 보관 트리거, 정기 학생 편성 규칙, 상담 세부 열람 권한·보존 기간, 방학과 운영 휴무의 연동 방식, 실시간 갱신 방식은 구현 전 확정한다. 미확정 정책을 기존 서비스의 검증된 동작으로 간주하지 않는다.

## 9. 디자인 점검 후 구체화한 동작

- 상담 행의 작업은 예약 ID와 대상자 ID를 유지한다. 결과 미기록에는 결과 작성, 기록 완료에는 기록 보기, 취소에는 취소 상세를 제공한다. 서로 다른 행이 동일 예시 기록으로 연결되는 구현은 허용하지 않는다.
- 상담 본문·결과·합의 사항은 여러 줄 입력을 지원한다. 후속 조치는 각각 내용·담당자·기한을 가지며 저장 시각과 기록 작성자를 확인할 수 있다.
- 저장 성공 후 해당 상담은 기록 완료로 표시하고 미기록 건수를 갱신한다. 저장 실패 시 입력을 보존하고 완료 상태로 이동하지 않는다.
- 보강 필터는 출석 미확인과 결과 미기록을 별도로 제공한다. 필터 건수는 고유 학생 기준임을 표시하고 교시별 배정 건수와 구별한다. 복수 보강이 허용되는 경우 학생/보강 건수의 표기 기준은 구현 시 데이터 구조와 일치시킨다.
- 연간 달력의 일정 날짜 표시와 월별 요약은 월간 일정과 같은 데이터에서 산출한다. 미등록 월을 명시하고 기간 일정은 모든 해당 날짜에 표시한다.
- 날짜·시작·종료·담당자는 독립 선택 요소로 제공한다. 상담 충돌 안내에는 겹치는 시간과 해당 상담을 제시한다. 보강의 여러 학생 동시 지도는 상담 충돌 규칙을 그대로 적용하지 않는다.
- 모바일 상담은 대상자 확인 → 결과 입력 → 저장 확인 → 완료 목록의 흐름을 지원한다. Figma의 대표 화면 연결을 실제 데이터 동작 완료로 간주하지 않는다.
