# MJE Back Office 기능 명세서

버전: v0.3 · 작성일: 2026-09-14 · 상태: 검토용 초안

**필수 범위 변경:** 알림장, 토요수업·보강, 교재 주문·교재비 청구, 수업료 청구·납부 확인을 모두 구현한다. 구체적인 입력·상태·권한·원본 근거·Figma 화면은 [필수 업무 명세 v0.3](required-workflows-v0.3.md)에 정리했다. 이전의 알림장·청구·수납 제외 방침은 폐기하며, 두 문서가 충돌하면 v0.3 확장 명세를 우선한다.

v0.2 변경: 사용자 요청에 따라 날짜별 보강 시간표와 관리자 토요일 근무 로테이션을 추가했다. 첨부된 시간표에서 여러 학생의 동시 보강을 확인하여 강사 시간 중복 차단 제안을 수정했다. 로테이션의 대체·휴무·적용 규칙은 검토용 설계안이다.

## 1. 목적과 문서 읽는 방법

영어 학원의 학생·알림장·토요수업/보강·교재 주문과 교재비·수업료 청구 및 납부·회의 후속 업무를 한곳에서 관리한다. 외부 서비스 자동 연동은 별도 결정하되 필수 업무 자체는 백오피스에서 처리·추적할 수 있게 한다.

- **요청**: 사용자가 직접 요청한 기능 영역이다.
- **설계안**: 요청을 실제로 사용할 수 있는 기능으로 구체화한 제안이다. 구현 완료나 운영 정책 확정을 뜻하지 않는다.
- **확인 필요**: 업무 방식에 따라 선택이 필요한 정책이다. 12절에 권장안을 모았다.

학생 관리·보강 관리·회의 기록·강사 및 관리자 로그인은 요청된 범위다. 이 문서의 세부 필드, 권한, 상태와 검증 규칙은 별도 표시가 없으면 **설계안**이다. 현재 Figma는 화면 이동 시안이며 실제 로그인·저장 기능은 구현되지 않았다.

## 3. 사용자와 권한

### 3.1 권한 기준안

계정의 저장된 역할로 권한을 판단한다. 로그인 화면의 역할 선택으로 권한을 부여하지 않는다. 아래 표는 구현 기준으로 제안하며, 강사의 담당 외 학생 접근과 회의 공유 범위는 확인이 필요하다.

| 행동 | 관리자 | 강사 |
| --- | --- | --- |
| 학생 목록·상세 조회 | 전체 | 본인이 담임 또는 원서 담당인 학생 |
| 학생 등록 | 가능 | 불가 |
| 이름·학교·학년·보호자 연락처 수정 | 가능 | 불가 |
| 담임·원서 담당·정규 시간표·재원 상태 변경 | 가능 | 불가 |
| 수업 메모·알림장 링크 수정 | 가능 | 담당 학생만 가능 |
| 보강 등록 | 전체 학생 | 담당 학생 |
| 보강 조회 | 전체 | 담당 학생 또는 본인이 보강 담당인 건 |
| 보강 일정·전달 사항·결과 수정 | 전체 | 담당 학생 또는 본인이 보강 담당인 건 |
| 보강 취소·최종 결과 정정 | 가능 | 불가; 관리자에게 요청 |
| 토요일 근무표 조회 | 전체 | 본인 근무일 및 업무상 필요한 근무자 정보 |
| 로테이션·날짜별 대체·휴무 변경 | 가능 | 불가 |
| 회의 조회·작성 | 가능 | 가능; 공유 범위는 아래 기준 적용 |
| 회의 본문 수정 | 전체 | 본인이 작성한 회의 |
| 후속 업무 담당·기한 변경 | 전체 | 해당 회의 작성자 |
| 후속 업무 완료·완료 취소 | 전체 | 해당 업무 담당자 또는 회의 작성자 |

보강만 맡은 강사는 해당 보강에 필요한 학생 이름·학년·수업 메모를 조회한다. 보강 배정만으로 학생 전체 상세나 보호자 연락처 접근 권한을 추가하지 않는 안을 제안한다.

회의는 초기 운영을 단순하게 하기 위해 전체 재직 강사에게 공유하는 안을 제안한다. 학생 연결은 학생 상세 접근 권한을 확대하지 않는다. 다만 회의 본문에 직접 쓴 학생 정보는 회의 독자에게 보이므로, 제한된 상담 기록을 함께 작성해야 한다면 구현 전에 회의별 공개 범위를 별도로 설계해야 한다.

### 3.2 공통 접근 규칙

- 화면에서 버튼을 숨기는 것과 별개로, 조회·저장 요청마다 서버에서 권한을 확인한다.
- 계정이 비활성화되면 기존 로그인 상태에서도 이후 접근을 차단한다.
- 권한 없는 주소로 직접 접근하면 내용을 반환하지 않고 접근 불가 안내를 표시한다.
- 담당 변경 후에는 변경된 담당 관계를 적용한다. 기존 작성자라는 이유만으로 학생 접근을 유지하지 않는다.
- 학생 휴원·퇴원과 계정 비활성화는 구분한다. 학생 상태 변경은 기존 이력을 삭제하지 않는다.

## 5. 로그인 및 계정

| ID | 기능 | 동작 및 완료 기준 |
| --- | --- | --- |
| AUTH-01 | 로그인 | 이메일·비밀번호를 입력한다. 성공하면 관리자에게 전체 학생 목록, 강사에게 담당 학생 목록을 표시한다. |
| AUTH-02 | 로그인 오류 | 누락·이메일 형식 오류는 해당 입력란에 표시한다. 인증 실패는 계정 존재 여부를 구분하지 않는 안내를 표시한다. 비밀번호를 화면이나 로그에 남기지 않는다. |
| AUTH-03 | 로그인 유지·종료 | 로그아웃 시 로그인 상태를 종료한다. 만료 시 로그인 화면으로 이동하고 재로그인 필요를 안내한다. 이메일 기억하기는 이메일만 기억한다. |
| AUTH-04 | 계정 운영 | 공개 가입 없이 학원에서 계정을 발급한다. 발급·초기 비밀번호 변경·분실 복구·비활성화 경로는 구현 전 결정한다. 초기 관리자 계정도 별도로 준비해야 한다. |

비밀번호 찾기는 실제 복구 경로가 정해지기 전에는 자동 재설정을 약속하지 않는다. 관리자 수동 재발급 방식으로 시작할 경우 화면에도 관리자 문의 경로를 명시한다. 세션 만료 시간과 재발급 절차는 확인 필요 항목이다.

## 6. 학생 관리

### 6.1 입력 정보

| 항목 | 필수 | 규칙 |
| --- | --- | --- |
| 학생 ID | 자동 | 변경되지 않는 내부 식별자. 동명이인을 이름만으로 구분하지 않는다. |
| 이름 | 필수 | 앞뒤 공백 제거, 빈 문자열 불가 |
| 영어 이름 | 선택 | 검색 보조 정보 |
| 학교 / 학년 | 선택 | 모르는 정보로 등록을 막지 않는다. 학년은 미취학·초등·중등·고등·기타 구분을 지원한다. |
| 보호자 연락처 | 선택 | 연락처가 있으면 전화번호 형식을 확인한다. 필수 여부는 운영 확인 필요. |
| 담임 강사 | 필수 | 활성 강사 계정 중 한 명 선택 |
| 원서 담당 강사 | 선택 | 활성 강사 계정 중 한 명 선택. 담임과 같아도 된다. |
| 재원 상태 | 필수 | 재원·휴원·퇴원, 신규 기본값은 재원 |
| 정규 수업 일정 | 선택 | 첫 버전은 요일·시간을 설명하는 문자열. 자동 시간 충돌 검사나 회차 계산에 사용하지 않는다. |
| 첫 수업일 | 선택 | 날짜만 기록. 가입일과 구분한다. |
| 교재·과정 및 수업 메모 | 선택 | 수업 인수인계에 필요한 내용 |
| 기존 알림장 URL | 선택 | 유효한 HTTPS 주소. 초기에는 Google Docs/Sheets 문서 링크를 허용하는 안을 제안한다. |

### 6.2 기능 상세

| ID | 기능 | 동작 및 완료 기준 |
| --- | --- | --- |
| STU-01 | 학생 등록 | 관리자가 필수 항목을 입력해 저장한다. 성공 시 학생 ID를 생성하고 상세로 이동한다. 이름이 같아도 등록 가능하며 이름·학교가 같은 기존 학생이 있으면 중복 확인 안내를 제공한다. |
| STU-02 | 목록·검색·필터 | 이름·영어 이름 검색, 담당 강사·재원 상태 필터를 조합한다. 기본값은 재원 학생이다. 강사에게는 권한이 있는 결과와 건수만 반환한다. 동명이인은 학교·학년·담당을 함께 보여준다. |
| STU-03 | 상세·수정 | 기본 정보, 담당, 시간표, 메모를 표시한다. 권한이 있는 항목만 수정할 수 있다. 저장 실패 시 입력을 유지한다. |
| STU-04 | 상태·담당 변경 | 재원↔휴원↔퇴원 전환이 가능하다. 상태를 바꿔도 보강·회의 이력을 유지한다. 미완료 보강이 있으면 알리고 자동 취소하지 않는다. |
| STU-05 | 관련 기록·알림장 | 학생의 알림장·학습 이력, 미완료/과거 보강, 관련 회의 안건으로 이동한다. 권한에 따라 교재·청구 상태도 연결한다. 기존 알림장 링크는 과거 자료 참고용으로 새 탭에서 연다. |

학생 삭제 버튼은 초기 범위에서 제공하지 않는 안을 제안한다. 오등록 정리·개인정보 삭제 요청은 보관 정책과 함께 별도 처리 방식을 확정한다. 같은 학생의 중복 등록을 합치는 기능은 초기 범위 밖이다.

## 7. 보강 관리

### 7.1 입력 정보

보강 한 건은 학생 한 명의 원래 결석 수업 한 건에 연결한다. 백오피스 출결에서 선택하거나 과거 자료의 결석일을 직접 입력한다. 같은 날짜 복수 수업은 수업 ID로 구분한다.

| 항목 | 필수 | 규칙 |

### 7.3 기능 상세

| ID | 기능 | 동작 및 완료 기준 |
| --- | --- | --- |
| MKP-01 | 미정 등록 | 보강 날짜 없이 먼저 저장한다. 학생 상세와 보강 목록의 일정 미정 영역에서 확인한다. |
| MKP-02 | 일정 지정·변경 | 날짜·시간·담당 방식을 지정해 예정으로 저장한다. 같은 학생의 다른 예정 보강과 시간이 겹치면 저장을 막는다. 한 강사가 여러 학생을 동시에 지도하는 것은 허용하고 동시 인원을 보여준다. 토요일 근무자 따름은 확정된 날짜별 근무가 있을 때 선택할 수 있다. 정규 수업 일정과의 자동 대조는 하지 않는다. |
| MKP-03 | 목록·검색 | 학생 이름, 상태, 보강 담당, 날짜 범위로 조회한다. 예정·완료·불참의 날짜 필터는 보강일 기준이다. 날짜가 없는 미정 건은 별도 영역에서 항상 확인할 수 있게 한다. |
| MKP-04 | 결과 기록 | 예정 건을 완료 또는 불참으로 처리하고 결과 메모·처리자·처리 시각을 저장한다. 목록과 학생 상세에 같은 결과가 반영된다. |
| MKP-05 | 취소·정정·이력 | 관리자 취소·정정은 이유를 기록한다. 기록을 물리적으로 삭제하지 않는다. 이전 일정·담당·상태와 변경자를 확인할 수 있다. |

추가 검증 규칙:

- 같은 학생·결석일의 미정 또는 예정 보강이 있으면 기존 건을 안내하고 중복 등록을 막는 안을 제안한다. 하루에 복수 수업을 보강해야 한다면 결석 수업 구분 필드가 필요하므로 구현 전에 정책을 확정한다.
- 불참·취소 기록이 있는 결석일의 새 보강은 관리자만 사유를 남겨 생성하는 안을 제안한다. 자동 재보강을 만들지 않는다.
- 휴원·퇴원 학생도 기존 약속을 처리할 수 있도록 관리자 보강 등록을 허용한다. 강사의 신규 등록은 재원 담당 학생으로 제한한다.
- 과거 보강일 입력은 실제 기록을 뒤늦게 정리하는 경우를 고려해 허용한다. 상태는 자동 완료로 바뀌지 않는다.
- 연결 학생이 바뀌지 않는 범위에서 결석일 정정은 관리자만 수행하며 중복 검증을 다시 적용한다.

원본 업무 문서에는 결석 후 한 달 내 보강, 보강 불참 후 재보강 제한, 사전 협의 예외 등의 운영 규칙이 있다. **현재 적용 여부와 예외 승인 절차를 확인하기 전에는 기한 초과 차단·환불 계산·자동 취소로 구현하지 않는다.**

| ID | 기능 | 동작 및 완료 기준 |

- 표는 시작 시간 기준의 묶음이다. 10:00–12:00 수업을 11시 영역에 중복 표시하지 않으며 학생 수와 건수를 중복 집계하지 않는다.
- 표 머리글과 시간 열은 스크롤 시 유지하는 안을 제안한다. 긴 전달 메모는 행 높이를 늘려 읽을 수 있게 하고 상세에서 전체 내용을 확인한다.
- 기본 시간표는 예정 건을 표시한다. 완료·불참 기록은 상태 필터로 확인하며 취소는 기본 제외한다. Figma는 예정 건의 예시다.
- 일정 미정은 날짜 시간표에 섞지 않고 별도 건수·진입 버튼으로 제공한다. 보강이 없는 날짜와 근무자가 미배정인 날짜를 구분한다.
- 동일 강사의 동시 학생 수는 참고 정보로 표시한다. 정원에 따른 차단은 정원 정책이 정해진 뒤 별도 검토한다.
- 원래 담임, 날짜별 토요일 근무자, 개별 지정된 보강 강사를 구분한다. 개별 담당 보강은 시간표의 전달 영역에 담당자 표시를 추가한다.
- 토요일 근무자는 해당 근무에 연결된 보강의 학생 이름·학년·담임·결석일·교재·메모를 볼 수 있다. 보호자 연락처나 학생 전체 상세 권한을 추가하지 않는다. 다른 강사는 기존 담당 관계 범위로 조회한다.
- 정규 토요수업도 필수 범위다. 결석일 없이 등록하고 시간표에 정규/보강 유형을 표시한다. 구조화된 정규 일정에서 가져오는 기능과 중복 방지는 v0.3 명세를 따른다.

### 7.5 관리자 토요일 근무 로테이션

사용자가 요청한 것은 토요일 순환 근무를 관리자가 반영하는 기능이다. 다음은 **매주 토요일 1명 근무** 기준의 기본 편성 제안이다. v0.3 원본 재확인에서 발견한 비상 대체 순번은 별도로 관리하며, 기본 근무와의 관계·복수 근무자·교대 여부는 확인이 필요하다.

| ID | 기능 | 입력·동작 및 완료 기준 |
| --- | --- | --- |
| ROT-01 | 기본 로테이션 설정 | 활성 강사 목록에서 근무 순서를 지정한다. 추가·제외·위/아래 이동, 시작 토요일, 적용 종료일, 기본 시작·종료 시간을 설정한다. 중복 강사·빈 순서·종료≤시작·역전된 적용 기간을 저장하지 않는다. |
| ROT-02 | 편성 미리보기·저장 | 시작 토요일의 첫 강사부터 주별로 순환한다. 저장 전에 날짜별 기본 순서·실제 적용 강사·신규/유지 여부를 표시한다. 기간 내 미편성 날짜만 생성하며, 지난 근무·확정 근무·대체·휴무 기록을 자동 덮어쓰지 않는다. 저장 후에만 강사 화면에 반영한다. |
| ROT-03 | 날짜별 대체 근무 | 관리자가 날짜·대체 강사·시간·사유를 입력한다. 원래 순서와 실제 근무자를 함께 보존한다. 그 날짜만 변경하고 이후 순환 순서는 유지한다. 변경자·시각·사유를 기록한다. |
| ROT-04 | 휴무·연결 보강 확인 | 휴무 전 연결된 예정 보강을 다른 날짜로 이동하거나 취소하도록 안내한다. 남아 있으면 휴무 저장을 차단한다. 근무 시간 축소 시 근무 밖으로 벗어나는 연결 보강을 먼저 조정해야 한다. |

연결 및 예외 규칙:

1. 토요일 보강의 담당 방식이 **근무자 따름**이면 해당 날짜별 근무에 연결한다. 미편성 날짜에는 미배정 안내를 표시하고 편성 후 일정 확정 또는 관리자 개별 담당 지정을 안내한다. 등록·수정 화면의 담당 방식 선택은 후속 상세 디자인 대상이다.
2. 대체 근무 저장 전에 영향을 받는 연결 예정 보강 수와 기존/변경 강사를 보여준다. 사용자가 변경 저장을 누르면 근무와 그 근무를 따르는 예정 보강 담당을 함께 변경한다. 개별 지정 보강·완료·불참 기록은 자동 변경하지 않는다.
3. 보강 날짜를 옮길 때는 새 날짜 근무 연결을 다시 확인한다. 평일로 옮기면 개별 담당을 지정한다. 원래 담임·교재·결석일은 변경하지 않는다.
4. 휴무도 달력상의 순번 한 주를 차지하고 다음 주 순번은 유지하는 안을 제안한다. 공휴일 여부만으로 자동 휴무를 생성하지 않는다.
5. 순서 변경은 미리보기에서 미편성 날짜에만 적용한다. 기존 확정 날짜의 변경은 날짜별 변경 기능을 사용한다. 같은 조건으로 다시 저장해도 날짜별 근무가 중복 생성되지 않는다.
6. 비활성 강사는 새 편성·대체 후보에서 제외한다. 이미 배정된 미래 근무는 경고하고 관리자에게 재배정을 요청한다. 과거 담당 이력은 유지한다.
7. 여러 관리자가 동시에 편성하거나 연결 보강이 변경된 경우 최신 상태를 다시 확인하게 한다. 근무만 바뀌고 보강 담당 변경은 실패하는 부분 저장을 허용하지 않는다.

데이터는 로테이션 설정(순서·적용 기간·시간)과 날짜별 근무(날짜·원래 순번·기본 강사·실제 강사·근무/휴무·변경 사유)를 구분한다. 보강에는 연결 근무 ID와 담당 방식을 기록하며, 당일 전달 사항은 날짜별 기록으로 관리한다.

| MTG-01 | 회의 작성·공유 | 제목·날짜·참석자와 안건을 입력해 저장한다. 초기에는 저장 즉시 공유하며 별도 초안·승인 단계를 두지 않는 안을 제안한다. Figma의 ‘회의 공유’ 버튼은 이 저장 동작에 해당한다. |
| MTG-02 | 목록·검색·상세 | 제목·안건 내용 검색, 회의일 범위·참석자 필터를 제공한다. 상세에서 안건별 논의·결정과 후속 업무를 함께 확인한다. |
| MTG-03 | 회의 수정·학생 연결 | 작성자 또는 관리자가 수정한다. 학생 선택창에는 본인이 조회 가능한 학생만 제공한다. 학생 상세에는 권한이 있는 관련 회의 링크를 표시한다. |
| TASK-01 | 후속 업무 등록·수정 | 담당자·기한을 지정한다. 활성 계정 중 담당자를 선택한다. 완료하지 않은 업무의 기한이 지나면 기한 경과로 표시한다. 별도 알림은 발송하지 않는다. |
| TASK-02 | 완료·완료 취소 | 담당자·회의 작성자·관리자가 완료 처리한다. 완료 취소도 가능하며 변경자를 기록한다. 완료한 업무를 목록에서 삭제하지 않고 완료 상태로 남긴다. |

회의 저장은 본문·안건·후속 업무를 한 번에 저장한다. 일부만 저장된 상태를 성공으로 표시하지 않는다. 후속 업무를 완료하면서 동시에 다른 사람이 회의 내용을 수정해도 완료 상태가 과거 값으로 덮어써지지 않아야 한다.

후속 업무가 연결된 안건은 바로 삭제하지 않는다. 업무를 다른 안건에 연결하거나 회의 공통 업무로 변경한 후 제거한다. 이미 공유된 회의 전체 삭제는 초기 화면에서 제공하지 않고, 오등록은 제목·본문 정정으로 표시하는 안을 제안한다.

회의에서 보강 필요가 결정되더라도 보강은 수동으로 등록한다. 회의 업무 완료와 보강 완료는 서로 다른 상태이며 자동으로 연동하지 않는다.

## 9. 공통 동작과 데이터

### 9.1 데이터 관계

| 데이터 | 주요 연결 |
| --- | --- |
| 계정 | 역할·활성 여부, 담당 학생, 보강, 회의 작성·참석, 후속 업무 담당 |
| 학생 | 담임 1명, 원서 담당 최대 1명, 여러 보강, 여러 회의 안건 |
| 보강 | 학생 1명, 담당 강사 1명, 원래 결석일, 일정·상태·결과 |
| 회의 | 작성자 1명, 참석자 여러 명, 안건 1개 이상, 후속 업무 0개 이상 |
| 안건 | 회의 1개, 관련 학생 0~1명 |
| 후속 업무 | 회의 1개, 안건 0~1개, 담당자 1명, 기한·완료 정보 |
| 변경 이력 | 대상 기록, 변경자·시각, 변경 항목·이전 값·새 값·정정 사유 |

이름이 바뀌어도 연결은 ID로 유지한다. 계정을 비활성화해도 과거 작성자와 담당자 이름은 이력에 남긴다. 학생의 현재 담당 변경은 이미 지정된 보강 담당자를 자동 변경하지 않는다.

### 9.2 화면·저장 규칙

| ID | 규칙 |
| --- | --- |
| COM-01 | 날짜와 시간은 한국 시간 기준으로 표시한다. 결석일·회의일·기한은 날짜이며, 생성·수정 시각과 구분한다. |
| COM-02 | 필수값·형식 오류는 입력 위치에 안내한다. 저장 중 중복 클릭을 막고, 성공 응답을 받은 뒤에만 완료 안내와 목록 변경을 표시한다. |
| COM-03 | 저장 실패 시 입력을 유지하고 재시도할 수 있다. 응답 유실 후 재시도해도 같은 등록이 두 건 생기지 않도록 처리한다. |
| COM-04 | 조회 중·데이터 없음·검색 결과 없음·조회 실패를 구분한다. 조회 실패를 빈 명단처럼 보여주지 않는다. |
| COM-05 | 수정한 내용을 저장하지 않고 이동하려 하면 이탈 여부를 확인한다. 자동 저장은 초기 범위에 포함하지 않는다. |
| COM-06 | 다른 사용자가 먼저 수정한 기록을 오래된 화면에서 저장하면 덮어쓰지 않고 최신 내용 확인을 요청한다. 입력 내용은 복사하거나 다시 반영할 수 있도록 유지한다. |
| COM-07 | 목록은 페이지로 나눈다. 학생은 이름·ID 순, 보강은 날짜·시간·ID 순, 회의는 회의일·ID 내림차순으로 안정적으로 정렬한다. 미정 보강은 등록 오래된 순으로 표시한다. |
| COM-08 | 상태는 색과 글자를 함께 표시한다. 입력에는 항목명을 붙이고 키보드로 주요 입력·저장을 수행할 수 있게 한다. |

조회 가능한 데이터만 검색·건수·관련 기록·선택창에 포함한다. 비밀번호는 안전한 단방향 방식으로 보관하며, 개인정보를 오류 로그에 기록하지 않는다. 변경 이력도 원본과 같은 접근 제한을 적용한다.

최소 변경 이력 대상은 학생 담당·재원 상태·연락처, 보강 일정·담당·상태·결과, 회의 본문 수정, 후속 업무 담당·기한·완료 상태다. 상세 이력 조회 화면의 범위와 보관 기간은 구현 전 확정한다.

현재 디자인은 데스크톱 기준이다. 모바일 전용 화면은 이번 시안 범위 밖이며, 강사가 휴대전화로 업무를 처리해야 한다면 구현 우선순위에 반영해야 한다.

## 11. 권장 구현 순서

1. **로그인·학생·수업 일정**: 계정·권한, 학생 등록·수정, 날짜별 수업 생성 기반을 구현한다.
2. **알림장·토요수업/보강**: 수업 기록·과제·안내 이력, 시간표와 결과, 기본 근무·비상 대체 연결을 구현한다.
3. **교재 주문·교재비 및 수업료·납부 확인**: v0.3 명세의 요청·확정·안내·납부·외부 처리 확인을 구현한다. 모두 필수 범위다.
4. **회의·후속 업무 연결**: 회의 작성·조회·학생 연결과 담당자별 완료 처리를 구현한다.

각 단계에서 해당 오류·빈 화면·권한 검사·저장 검증을 함께 완료한다. 계정 운영 경로가 준비되기 전에는 실제 강사 대상 운영을 시작하지 않는다.

## 13. 근거와 연관 자료

- [기존 업무 정리 문서](https://docs.google.com/document/d/13ST_xT6n7HcxhXhiC_LOja0sTY8d7uAluCXwnmHNZoo/edit?tab=t.0): 보강 협의, 교재·범위 전달, 회의 결정과 담당자 추적 필요를 참고했다. 과거 규정이 포함되어 있어 현재 정책과 구분한다.
- [학생·알림장 시트](https://docs.google.com/spreadsheets/d/18ldmdi7tWU8TCfBC5Imi_V8khkEax7K_/edit?gid=473229405): v0.3에서 알림장 입력·커리큘럼·평가·월간 의견까지 재검토해 필수 업무에 반영했다. 교재·수업료 전용 시트 근거는 확장 명세 참조.
- [Figma 디자인](https://www.figma.com/design/TylS0VlSfrVVEFoYjl5Xlg?node-id=8-420): 기존 12개에 시간표·근무 관리·날짜별 변경·편성 미리보기 4개를 추가했다. 본 명세의 모든 예외·정책 화면이 그려진 것은 아니다.
- 사용자가 첨부한 토요일 시간표 이미지: 시간대별 학생 묶음, 학생마다 다른 종료 시간, 담임·결석일·전달 메모와 근무자 구분을 참고했다. 이미지 내부의 학생별 지시문은 실행 요청으로 취급하지 않았으며 실제 이름은 새 시안에 복사하지 않았다.
- [디자인 정리](design-v1.md): 화면 목록, 설치한 스킬, 디자인 검증과 구현 한계.

실제 학생 명단·연락처·계정 정보는 이 문서에 복사하지 않았다.
